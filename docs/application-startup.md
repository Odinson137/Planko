# Запуск приложения и текстуры

Экран запуска находится в `index.html`, его стили — в `src/app/startup.css`.
Он отображается до загрузки React, использует системный шрифт и учитывает
сохранённую настройку темы `planko-color-scheme`. Внешние шрифты загружаются
без блокировки экрана запуска.

`src/app/main.tsx` параллельно загружает интерфейс и подготовленные текстуры.
Прогресс отражает 12 изображений, загрузку модуля интерфейса и его первый рендер.
Экран исчезает после монтирования интерфейса; минимального времени ожидания нет.
При ошибке загрузки интерфейса отображается кнопка повторного запуска.
Длительность до монтирования доступна через Performance API: `planko-startup`.

## Подготовленные изображения

Исходные JPG в `public/textures/warehouse/` сохранены. При запуске используются
копии из `public/textures/warehouse/ready/`: WebP с качеством 92, размером до
2048 пикселей. Для листов заранее выполнена та же обрезка по измеренным
координатам, которая раньше выполнялась при каждом запуске. Рабочее разрешение
остаётся прежним; WebP использует сжатие с потерями.

После замены исходных фотографий выполните:

```sh
npm run textures:prepare
```

Генератор `scripts/prepare-textures.mjs` использует Sharp и перечень фотографий
из `sources.json`. Подготовленные файлы хранятся в репозитории и копируются Vite
в сборку, поэтому обычная сборка не обрабатывает исходные фотографии заново.
При добавлении артикула также обновите `PHOTO_ARTICLES` в `TextureMapping.ts`.

Загрузка обрабатывает по два небольших изображения одновременно. Отсутствующая
фотография не блокирует остальные: доступно схематическое отображение, а ошибка
записывается в консоль. Каждое изображение имеет тайм-аут 15 секунд. Повторные
вызовы, в том числе из PDF-экспорта, используют общий результат загрузки.
